# M4 数字守门员 — 方法、口径、局限、自检

产物：`demo/data/m4_gatekeeper.json`（本地 Python）。脚本：`gatekeeper.py`（子命令 extract / tieout / check / all）、`gk_core.py`（核心库）、`inject.py`（--seed、--n）、`test_gatekeeper.py`、`m4_checker.js`（网页实时检查器参考实现，已用 node 实测）。
全部为确定性代码（正则 + 单位归一 + 四舍五入区间比较），不靠大模型判断。本模块**未发起网络请求**：10-12 发债公告已在 `data/src/ir_official/`。内部准备材料，不构成公司口径。

## 复现
```
python -I demo/pipeline/gatekeeper.py all          # 约 6 秒，写 m4_gatekeeper.json
python -I demo/pipeline/test_gatekeeper.py         # 13 项测试
python -I demo/pipeline/inject.py --seed 7 --n 30  # 单独生成注入稿与答案
python -I demo/pipeline/gatekeeper.py check --draft <每段一行的草稿> [--twin <另一语言草稿>]
```

## 方法
1. **文本层**：原 `data/src/ir_official/*.txt` 是 pdftotext 的 Latin-1 输出，中文全部丢失、英文表格列被打散。改用 PyMuPDF 对同一批 PDF 重新抽取 UTF-8 文本，落盘 `demo/data/raw/m4/txt/`（每页以 `=== page N ===` 开头）。所有 `line` 指派生文本行号；`txt_line` 为原 pdftotext .txt 同页含该数字的行号，便于交叉核对。港交所中文公告为繁体，逐字繁→简（长度不变）后再匹配。
2. **单位归一**：金额统一为"百万"（RMB/HKD/USD；billion=1000、亿=100、百万=1、万=0.01），无量级的人民币金额（每股、汇率）单列；数量（MAU、股数）统一为百万；百分比、百分点分开。每个数字带"半个末位单位"的四舍五入容差。
3. **注册表（66 个指标，≥40）**：逐句（别名 → 其后第一个同类数值/增减表述）+ 逐表行（标签 → 首列）抽取；Non-IFRS/IFRS 由段首口径标记与"Non-IFRS"前缀判别；"六个月/全年/年内"语句、比较期表述（compared with / …日的 / 由 X 增至 Y 取 Y）不计入本季。各文件取值按四舍五入区间聚类，优先含港交所表格的簇，取最精确者为规范值；利润率、经营开支为计算值（标"计算"）。
4. **五方勾稽**：指标 × 5 文件 → 一致 / 不一致 / 未出现。表格行须"首列等于规范值"或"第二列等于上年同季/上一季规范值"才视为本季口径（否则忽略，避免把六个月表、分部列表误判）。不一致项给出两边原文行并分类：四舍五入（判定一致）/ 末位差异 / 数量级或单位差异 / 实质差异；末位差异另算"同精度四舍五入值"与"截断值"。
5. **capex 三口径**：会计口径取港交所业绩公告"其他财务资料"表（与 2026 中报第 526 行一致）；现金口径取 10-12 发债公告"amount paid"段；季度资本开支付款取新闻稿/港交所公告/中报的 FCF 段（已核实）。
6. **草稿检查规则**：R1 数值≠已披露、R2 同比/环比方向或幅度、R3 中英文逐数配对（按全文数字序号就近配对）、R4 分部之和/FCF/净现金/capex 勾稽、R5 利润率与数值、R7 美元换算；以上标红。R6（黄）草稿数字未在港交所公告/PPT 的同语境（至少共享 1–2 个实词，中文经小型术语表可对英文 PPT）中出现 → 疑似未披露新数字。
7. **注入测试**：2Q26 中英文新闻稿正文为草稿，`inject.py` 用固定种子在本季度口径段落注入 30 处、7 类各 4–5 处；候选位置只用通用正则选取，不用检查器的别名表。检出 = 告警位置与注入位置重叠。误报测试 = 1Q25–1Q26 五个季度中英文新闻稿全部含数字段落（249 段），各以同季度港交所公告+PPT 为基准。
8. **js_registry**：66 个指标的规范值、容差、同比/环比参照、中英文写法变体与别名正则；`checker_js` 为可直接嵌入网页的检查器（"528→582" 即标红，已用 node 验证）。

## 结果（label：计算）
- 勾稽：66 指标 × 5 文件 = 330 格：一致 251、不一致 3、未出现 76。真实不一致：港交所中英文公告文字"一般及行政开支 RMB38.7 billion / 387 亿元"与同一公告表格 (38,808) 百万元不符（同精度应为 38.8）；PPT 经营开支 (50.6) 与 11,869+38,808=50,677 不符。四舍五入差异 6 例（如 PPT 36.9% vs 新闻稿 37%、PPT "up 1%" vs 0.8%、~RMB487 billion vs 487.2）。
- 其他季度同规则勾稽另得 22 条同类"文字 vs 表格"末位差异（1Q25/3Q25/1Q26 一般及行政开支、3Q25 分占联营、4Q25/1Q26 所得税等），多数与"截断取值"一致【推断】，列入需 IR/财务确认事项。
- capex：会计口径 2Q26 527.8 亿、1H26 847.2 亿（=1Q26 319.4+2Q26 527.8，勾稽通过）、FY2025 792.0 亿；现金口径 FY2025 883 亿、1H26 963 亿、1H25 459 亿；2Q26 资本开支付款 593 亿（已核实，五处出处）；1Q26 付款 370 亿为推算值。
- 注入（种子 7）：30 处检出 29（96.7%），七类中仅 ④ 为 3/4；样本外种子 101–120 共 600 处检出 591（98.5%）。误报：249 段中红色 1 段（0.4%），含黄色 11 段（4.4%）。

## 失败样例与局限（如实列出）
- **四舍五入掩盖**：英文写"2 million / 37.4 million"，中文改成"210万 / 3,741万"仍在英文精度范围内 → R3 无法发现（④ 的全部漏检属此类）。
- **注入相互干扰**：另一语言稿恰被注入同值数字（如英文改出 17%，中文新增"云服务收入同比增长17%"）时双语配对被"占位"，R6 又在公告中找到同值同语境 → 漏检。
- 唯一红色"误报"为 4Q25 中文"企业服务收入同比增长接近20%"对英文"high-teens rate"，人工复核为真实措辞差异；黄色主要是只在新闻稿出现的数字（季度回购港元金额、剔除新AI产品利润率 42%/39.9%、4Q25 全年总现金等）。
- 规则在开发中看过这些误报段落与种子 7，误报率与种子 7 召回率为样本内结果；101–120 种子为开发后一次运行。
- PPT 图表（无标签数字）、2Q25 PPT 文本顺序错乱的表格未能解析；表格行只取首列；分部毛利仅港交所公告有；正负号只对 FCF、分占联营、其他收益判断；繁简转换只覆盖公告常用字；JS 检查器只做别名语句的数值/同比核对（不含 R3/R4/R6 与表格行）。
- 规范值以港交所表格为准；文字与表格冲突时以表格为规范值并把文字列为不一致，不代表判断哪一方"错误"。

## 自检（写入 meta.self_check）
- 固定种子随机抽 10 个注册表数字，回到派生文本行与原 pdftotext .txt 行逐字比对：10/10 通过；另核对 4 条原句（发债公告 88.3/96.3、中报第 526 行 capex 行、中报 59.3 付款）：4/4 命中。
- 人工抽查（本次制作中逐一打开原文）：2Q26 新闻稿第 26 行 RMB204.8 billion；港交所英文 .txt 第 191 行 (38,808) 与第 326 行 RMB38.7 billion；PPT .txt 第 495 行 (50.6)、第 58 行 36.9%；发债公告 .txt 第 1709–1712 行 88.3/45.9/96.3；中报 .txt 第 526 行 84,720；新闻稿第 53 行 RMB59.3 billion；4Q25 港交所表格 79,198；1Q26 港交所第 308 行 RMB14.5 billion 与第 354 行 (14,577)；3Q25 第 329 行 RMB7.8 billion 与第 374 行 7,854——均与输出一致。
- 结构检查：所有含数值字段的对象均带 src 与 label，src id 均在 sources 中，label 均属四类；本模块自撰文字无禁用词、不含对股价与公司价值的评论；输出无邮箱、无含用户名的绝对路径（相对 ROOT 路径）。
