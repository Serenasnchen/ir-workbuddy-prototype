# M1 同业矩阵与速评：NOTES

内部准备材料，不构成公司口径。数据截止日 AS_OF = 2026-10-26。

## 产物与运行
- 输出：`demo/data/m1_peer.json`。主要字段有 `companies`、`topics`、`cells`（8×8，每格附上一季快照）、`capex_table`、`tencent_capex_trajectory`、`flashes`（Meta、阿里）、`rerun`、`rerun_method`、`sources`、`user_provided_sources`，自检结果写在 `meta.self_check`。
- 运行方式（在 ROOT 下）：
  1. `python -I demo/pipeline/peer_fetch.py`：只补下载缺失文件，本地文件齐全时不发任何请求，同时重写 `data/src/peers/manifest.tsv`。
  2. `python -I demo/pipeline/peer.py`：不联网。两次运行的产物 sha256 相同。
- 脚本分工：
  - `peer_fetch.py`：下载并登记。
  - `peer_data.py`：单元格、capex 数值、来源表、数字锚点，人工整理。
  - `peer_flash_data.py`：两份速评，人工整理。
  - `peer.py`：计算、校验、输出。
  - `sa_transcript.py`：解析实录。
- 产物标注为“本地 Python”：文字部分人工整理，数字和引语都由脚本逐字对过本地原文。

## 方法
1. **期间**：每家取截至 10-26 最近已发布的季度，另存上一季快照。
   - 已发布最新季：腾讯 2Q26、阿里 FY27Q1（截至 2026-06-30）、百度 2Q26、京东 2Q26、Meta 2026Q3（10-21 发布）。
   - 尚未发布、暂用上一季：Alphabet Q2'26、Microsoft FY26Q4、Amazon Q2'26。三家分别于 10-28、10-28、10-29 发布，日期见官方页 S33、S44、S53。
2. **单元格**：每格包含 value_short（不超过 20 字）、detail、src、label、quote 和 change_vs_prior。
   - quote 英文不超过 25 词，中文不超过 40 字，可以为空。
   - change_vs_prior 由人工比对新旧快照后填写，状态为实质变化、口径变化、无变化或新增，并附说明。
   - 另有自动标记 `auto_diff`，显示 value_short 是否变化。
3. **构建即校验**：任何一项不通过，脚本退出码为 1，且不写产物。校验项：
   - 字数上限、label 合法、src 都已登记；
   - 引语在本地来源文件中逐字出现，比对时只归一化空白、弯引号和连字符；
   - 数字锚点逐字出现；
   - T1 单元格的同比与 capex 表计算值相差不超过 1pp；
   - 人民币折美元后与公司自行披露的美元值相差不超过 1 百万；
   - 速评固定为 3 条结论、2–3 条引语、3 条启示（均标推断）、3 个问题；
   - 扫描禁用词（按 CONTRACT.md 第 4 节）、市场定价类用语、邮箱、本机用户名和绝对路径。
4. **速评**：格式为结论先行 3 条、关键数字表、AI capex 与指引、管理层短引语、分析师追问焦点、对腾讯口径的启示、腾讯 Q3 可能被追问的问题。
   - 关键数字表每一行都带原文锚点。
   - “可能被追问的问题”只给问题和已公开表述索引（`public_statement_refs` 指向腾讯行单元格），不写答复建议，并注明“需管理层确认是否回应、如何回应”。

## 口径
- **capex 两列**：
  - 公司口径：公司自己称为 capex 或资本开支的数。
  - 现金口径：现金流量表中的购置物业设备，或公司 FCF 对账表中的扣减项。
  - 公司只披露一个数时，两列相同并标 `same_basis`。百度、京东、Alphabet 属于这种情况，它们披露的 capex 本身就是现金口径。
- **各家主要差异**：
  - 腾讯：公司口径 528 亿元，现金付款 593 亿元。大额算力预付款计入经营现金流。
  - Meta：含融资租赁本金。
  - Microsoft：公司口径含融资租赁，属非现金项。FY27 起更多新租赁计为经营租赁，口径会偏低；财年与日历年也错位。
  - Amazon：公司口径为扣除出售所得后的净额，含物流和 Kuiper。
  - 京东：含开发物业，未单列 AI 算力。
  - 每一行的 `comparability` 字段有说明。capex 表只用于口径对照，不宜直接排名。
- **汇率**：采用美联储 H.10 2026-06-30 的 RMB6.7851 = US$1，阿里、百度、京东公告都用这个汇率。腾讯没有美元折算，由脚本按同一汇率计算，标“计算”。
- **同比**：只有腾讯公司口径（+176%）和阿里公司口径（+75%）是公告直接披露，其余由脚本按原币百万计算。T1 单元格会自动加 `label_note`，写明“金额为公开披露；同比为计算值”。
- **label**：公开披露、结构化数据、计算、推断四种。条目里只要含计算值就标“计算”，含因果判断或预期就标“推断”。
- **tier**：3 级（第三方实录）的引语自动加注“非官方逐字稿，引用前以官方录音为准”；4 级加注“媒体转述/二手”。

## 自检结果（2026-10-26）
- **构建校验**：64 格（8×8）另加 64 格上一季快照。80 条引语、127 个数字锚点逐字比对通过。所有 src 都存在于 sources，label 合法。折美元结果与公司披露值相差不超过 1 百万。
- **随机抽查**：用固定种子 20261026，从能回溯到本地原始文件的条目中抽 14 条（7 条数字、7 条引语），改用不经实录解析器的原文文本重新查找，14/14 通过。明细见 `meta.self_check.random_spot_check`。
- **人工抽查**：16 条，涉及 Meta、阿里、百度、京东的公告和腾讯实录，发现并更正 5 处（见上）。明细见 `meta.self_check.manual_spot_check`。
- **扫描**：禁用词、市场定价类用语、邮箱、本机用户名、绝对路径的命中数都是 0。免责声明字段本身含红线用语，扫描时剔除。
- **负向测试**：人为篡改 1 条引语、1 个锚点、1 个 label，构建按预期失败，且没有写产物。

## 重跑（同业发布新季度后）
1. 在 `peer_fetch.py` 的 FETCH 中加入新季度新闻稿或 SEC 文件和实录的 URL，然后运行 `python -I demo/pipeline/peer_fetch.py`。
2. 在 `peer_data.py` 中为该公司新增期间快照：latest 改为新期间，prior 改为原来的 latest；同步更新 CAPEX、SOURCES、NUMBER_ANCHORS。
3. 逐格填写 change_vs_prior。速评如需切换公司，修改 `peer_flash_data.py`。
4. 运行 `python -I demo/pipeline/peer.py`：同比、折算和 T1 交叉校验自动重算，任何引语或数字在原文中找不到都会导致构建失败。议题列 T1–T8 不变。
